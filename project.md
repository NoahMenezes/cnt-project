# Problem Statement

We are building a complete secure document encryption and cryptography platform called “CipherVault”, which is a hybrid RSA–AES based web application designed for secure file encryption, decryption, cryptographic document generation, encryption workflow visualization, and security analysis. The main objective of the platform is to provide users with a centralized environment where they can securely upload files or text data, apply hybrid encryption techniques using RSA and AES algorithms, generate encrypted documents, decrypt protected files, analyze encryption strength, and understand how modern cryptographic systems operate internally.

The platform is intended to function as a professional cryptographic workspace rather than a basic encryption tool. Users should be able to upload different types of files such as TXT, PDF, DOCX, JSON, CSV, and image-based documents, securely encrypt them using AES symmetric encryption, protect AES session keys using RSA public-key encryption, and generate downloadable encrypted files that can later be decrypted using the correct RSA private keys. The application combines practical cybersecurity functionality with educational cryptographic visualization and analysis features.

The core concept of the project is based on hybrid encryption systems. AES is used for high-speed encryption of actual file content because symmetric encryption is efficient for handling large data, while RSA is used to securely encrypt and transfer AES session keys using public-key cryptography. The platform demonstrates how hybrid encryption systems combine the efficiency of AES with the secure key exchange properties of RSA to create modern secure communication and storage systems.

The application must provide a complete encryption workflow where users can upload files, select encryption settings, generate AES session keys, generate RSA key pairs, encrypt documents, package encrypted data into downloadable secure formats, and later decrypt the encrypted files using the correct decryption keys. The system should generate secure encrypted document formats containing encrypted file content, encrypted AES keys, encryption metadata, and cryptographic configuration details.

The platform should include a dedicated “Encrypt” page that acts as the primary encryption workspace of the application. Users should be able to upload files, configure AES settings such as key sizes and encryption modes, configure RSA settings such as modulus size and public exponents, and perform secure hybrid encryption operations. After encryption, the platform should generate downloadable encrypted files that store encrypted content along with RSA-protected AES session keys.

The project must also contain a “Decrypt” page where users can upload previously encrypted files and restore the original document using the appropriate RSA private keys. The decryption workflow should demonstrate how RSA decrypts AES session keys and how AES decrypts the original file content. The system should verify file integrity and provide detailed process logs showing each stage of the decryption process.

A major component of the application is the “Hybrid RSA–AES Lab”, which acts as an educational and experimental cryptography environment. This section should visually demonstrate the complete hybrid encryption process step-by-step. Users should be able to enter custom text messages, generate RSA keys, generate AES keys, encrypt messages using AES, encrypt AES session keys using RSA, simulate secure transmission, decrypt AES keys, and restore original plaintext messages. The purpose of this module is to help users understand how hybrid encryption systems work internally through interactive experimentation and process visualization.

The Hybrid RSA–AES Lab should support both secure and intentionally weak configurations so users can study how insecure implementations affect security. Users should be able to experiment with small RSA key sizes, weak passwords, and different AES encryption modes such as CBC, ECB, and GCM. The system should display generated AES keys, encrypted AES keys, ciphertext outputs, decrypted outputs, encryption durations, process events, and timestamped cryptographic logs.

The platform should also include a cryptographic analysis and reporting engine that evaluates encrypted documents and generated encryption configurations. The analysis system should calculate entropy values, randomness levels, encryption quality, and security scores. It should detect repeated patterns, low randomness, weak passwords, insecure RSA key sizes, and unsafe cryptographic configurations. The system should generate structured reports containing detailed encryption findings, recommendations, detected weaknesses, and overall security assessments.

The project must contain a complete “Reports” section where users can manage previously generated encryption reports and encrypted files. The reports system should support searching, sorting, filtering, downloading, viewing, and deleting reports. Each report should include file metadata, encryption settings, entropy measurements, RSA analysis, AES analysis, security recommendations, and overall security classifications.

A dedicated “Visualizations” page should also be included to display analytical insights and cryptographic statistics. This section should contain charts and graphs showing entropy distributions, encryption performance comparisons, RSA versus AES metrics, encryption timing statistics, security score trends, weakness distributions, and user activity analytics. The purpose of this page is to transform cryptographic data into meaningful visual insights for users.

The application should also contain a complete educational “Learn” section explaining important concepts related to cryptography and number theory. Topics should include RSA, AES, hybrid encryption, prime numbers, modular arithmetic, Euler’s Totient Function, entropy, public-key cryptography, symmetric encryption, and cryptographic best practices. Each topic should contain explanations, formulas, examples, and practical demonstrations so that the platform serves both as a secure encryption system and as a learning environment for cryptography students and researchers.

The platform must also provide a “Profile” page where users can manage their account information, encryption history, generated reports, uploaded files, recent activities, and security preferences. Users should be able to view account statistics such as total encrypted files, generated reports, average security scores, and recent encryption activity.

The overall application should follow a modular and scalable architecture using reusable React components, organized folder structures, centralized state management, API-based backend communication, and secure database storage. The system should support authentication, encrypted document storage, report history tracking, and secure user management. All pages should integrate seamlessly into the existing application structure while maintaining responsiveness and consistent navigation behavior.

The final platform should simulate the behavior of a real-world secure document encryption product and provide users with a complete cryptographic environment that combines secure file protection, hybrid encryption workflows, document generation, cryptographic analysis, reporting, visualization, and educational cryptography tools into one unified system.
