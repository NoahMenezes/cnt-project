We are building a complete cybersecurity and cryptography analysis web application called “Crypto Forensics Lab”, which is a professional-style RSA–AES hybrid encryption analysis and visualization platform focused on cryptographic inspection, encryption workflow understanding, security evaluation, entropy analysis, and forensic-level cryptographic reporting. The purpose of the platform is not simply to encrypt and decrypt messages, but to act as a complete interactive research and educational environment where users can upload encrypted files, analyze cryptographic structures, inspect RSA and AES configurations, study encryption randomness, detect weak implementations, visualize encryption behavior, and understand how hybrid encryption systems work internally.

The application should feel like a real-world cybersecurity SaaS platform used by researchers, students, security analysts, and cryptography enthusiasts. The system should contain multiple interconnected pages and modules that work together as one complete ecosystem. The Homepage and Dashboard pages already exist and are fully completed, including authentication and the primary application shell. All newly generated pages must integrate seamlessly into the existing application structure and automatically follow the same navigation system, component patterns, spacing system, layout logic, responsiveness, and overall UI language already established in the project. Do not redesign or regenerate the Homepage or Dashboard. All new pages must extend the existing application naturally.

The main idea of the project is centered around hybrid encryption systems, specifically combining RSA and AES encryption concepts into one integrated educational and analytical environment. The application should explain, demonstrate, analyze, and visualize the relationship between RSA public-key cryptography and AES symmetric encryption, showing how RSA can be used to securely encrypt AES session keys while AES handles high-speed data encryption. The platform should simulate realistic cryptographic workflows while also providing forensic-style analysis tools that evaluate uploaded data and detect security weaknesses or insecure configurations.

The application must include an “Analyze” page, which acts as the core cryptographic analysis engine of the platform. This page should allow users to either upload encrypted files or manually paste encrypted text directly into the system. The page should support multiple file formats such as TXT, PDF, JSON, DOCX, and CSV. After the user uploads a file or enters encrypted data, the system should process the content through multiple cryptographic analysis modules and generate detailed forensic-style reports. The analysis workflow should include entropy analysis, RSA security inspection, AES security evaluation, pattern detection, randomness measurement, encryption structure observation, and overall security scoring.

The entropy analysis module should calculate randomness levels and determine whether the uploaded content appears highly random, moderately random, or predictable. The page should display entropy values, randomness classifications, entropy interpretations, and explanations of why entropy matters in cryptography. The RSA analysis section should inspect RSA-related configurations such as modulus size, key size, exponent values, and potentially weak configurations. The system should identify insecure RSA implementations, weak key lengths, suspicious exponent values, and unsafe setups. The AES analysis section should evaluate password strength, key complexity, AES mode configurations, and general symmetric encryption quality. The system should determine whether passwords are weak, predictable, or sufficiently secure.

The Analyze page must also include a pattern detection engine capable of identifying repeated character sequences, repeating data blocks, visible patterns, and structural anomalies that may indicate weak encryption or low randomness. The results page should present all findings inside organized analysis sections with clearly separated categories and structured forensic reporting. A centralized security score engine should combine entropy analysis, RSA findings, AES findings, and pattern analysis into one overall security score that classifies uploaded data into categories such as Secure, Moderate, Weak, or Critical. The page should also generate recommendations and improvement suggestions dynamically based on the detected weaknesses.

The platform must include a dedicated “Hybrid RSA–AES Lab” page that acts as an interactive cryptographic simulation environment. This page should visually demonstrate the entire hybrid encryption workflow step-by-step. Users should be able to enter custom messages, configure RSA settings, configure AES settings, generate RSA key pairs, generate AES session keys, encrypt messages using AES, encrypt AES keys using RSA, simulate transmission, decrypt AES keys using RSA, and finally decrypt the original message. Every step of the process should be separated into individual stages so users can understand exactly how hybrid encryption systems operate internally.

The Hybrid RSA–AES Lab should support both secure and intentionally weak configurations. Users should be able to experiment with smaller RSA keys, weak passwords, different AES key sizes, and different AES modes such as CBC, ECB, and GCM. The system should display generated AES keys, RSA encrypted AES keys, ciphertext outputs, decrypted messages, encryption durations, process logs, and timestamped cryptographic events. The purpose of this page is educational, analytical, and experimental. It should function like a cryptographic sandbox where users can safely explore how encryption systems work and how weak implementations affect security.

The application must also contain a dedicated “Visualizations” page that transforms cryptographic findings into graphs, statistics, and analytical dashboards. This page should aggregate data collected from analyses and display meaningful visual insights such as entropy distributions, security score trends, RSA versus AES comparison graphs, weakness distributions, encryption time versus file size graphs, character frequency distributions, and activity trends over time. Users should be able to filter analytical data using time ranges such as daily, weekly, monthly, or custom ranges. The page should function like a professional analytics center for cryptographic data and forensic metrics.

The project must include a “Reports” page where all previously generated analyses are stored and managed. This page should contain searchable and filterable report tables displaying uploaded files, file types, analysis dates, security scores, statuses, and available actions. Users should be able to search reports, sort reports, filter results, reanalyze files, view detailed forensic reports, download reports, and delete reports. Each report should contain a complete analysis summary including entropy findings, RSA findings, AES findings, recommendations, weaknesses, and overall risk assessments.

A complete “Learn” page must also be included to transform the project into a combined educational and analytical platform. This section should contain detailed educational material explaining important cryptographic and number theory concepts such as RSA, AES, hybrid encryption, prime numbers, modular arithmetic, Euler’s Totient Function, entropy, randomness, public-key cryptography, symmetric-key cryptography, and cryptographic best practices. Every topic should contain definitions, explanations, formulas, examples, practical use cases, and interactive learning examples. The Learn section should also contain mini quizzes, practice exercises, and interactive calculations that allow users to experiment with cryptographic formulas and concepts directly inside the platform.

The platform must also contain a complete “Profile” page where users can manage their accounts and view personal activity statistics. This page should display user information, account details, profile images, registration dates, total analyses performed, average security scores, generated reports, uploaded files, recent analyses, and session history. Users should also be able to modify account settings, security preferences, and notification settings from this page.

The entire application should follow a modular architecture with reusable React components, organized folder structures, centralized state management, reusable analysis modules, and scalable routing. The project structure should separate components, pages, charts, utilities, layouts, analysis engines, API services, and data models into clean independent modules. All pages must support responsive behavior and integrate naturally into the already existing navigation system and dashboard architecture.

The platform should simulate the behavior of a real professional cybersecurity product and should feel like a complete cryptographic research environment rather than a basic student encryption project. The application should combine cryptography, number theory, security analysis, data visualization, educational content, forensic reporting, and interactive encryption simulations into one unified system.
